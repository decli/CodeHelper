# 取件码助手（CodeHelper）

一款为老人场景设计的本地短信取件码助手。

## 功能

- 首屏默认读取最近 12 小时短信，只展示未取件码
- 首页采用「待取数量大数字」英雄区 + 时间筛选分段控件 + 待取列表的信息层级，打开应用第一眼就能看到还有几个包裹待取
- 全新「柿柿如意」视觉主题：柿橙表示待办、松绿表示完成，取件码以取件小票样式大字号居中展示，浅色 / 深色模式均已适配
- 时间筛选默认选中 `12小时`，点击 `其它时间` 会弹出大字号、大行高的时间选择面板，可直接选择 `1天内`、`2天内`、`3天内`、`5天内`、`7天内`、`14天内`，选择后立即重新读取短信
- 时间筛选有清晰选中态：选中分段为柿橙实心底 + 白色对勾（全应用统一的无边框实心选中语言）；选择其它档位后，分段控件会直接显示当前档位（如 `3天内`）
- 当前时间范围会扫描本机短信表中的全部短信记录，不再只依赖单一 `Inbox` 视图，减少同一发件人历史取件码漏读
- 同时兼容 `SMS + MMS` 两类本机接收消息，减少“菜鸟驿站”这类平台消息在系统短信列表可见、但应用内漏读的情况
- 仅展示本机收到的取件码，不展示本机发出的短信内容
- 待取数量统计会按未取件的实际取件码条数累加，同一短信里有 3 个取件码就计 3 个
- 桌面图标角标会显示当前时间范围内的未取件码数量，默认每 5 分钟自动刷新一次，刷新频率可在设置中调整；角标依赖一条可清除通知，手动清除通知或点击桌面图标导致角标隐藏后，会在下次刷新时重新发出通知并恢复
- 列表上方提供「待取包裹 / 全部包裹」双标签：点 `全部包裹` 会重新加载当前时间范围内的全部取件码（含已取件），点 `待取包裹` 回到默认视图，标签本身即状态指示，不再需要额外提示条
- 未取件卡片常驻 `我已取到` 大按钮与 `查看短信` 按钮，点 `我已取到` 立即标记为已取件并从待取列表消失，同时弹出带 `撤销` 的提示条支持一步恢复；左滑展开抽屉标记、双击卡片打开短信两个手势仍然保留
- 已取件卡片在 `全部包裹` 标签中始终排在未取件之后；未取件按短信时间倒序排列
- 卡片底部的识别说明显示实际命中的提示词（如 `识别依据：「取件码」`），自定义正则命中时显示 `高级规则N`
- 短信时间以 `今天 14:32`、`昨天 09:15` 的口语化格式展示，更早的短信显示完整日期
- 同一条短信里的多个取件码会聚合到一张卡片里，卡片内按行展示，每个取件码一行
- 默认提取逻辑会在 `取件码`、`提货码`、`货码`、`驿站码`、`凭` 等提示词后面，自动识别一个或多个由字母、数字、连字符组成的取件码，兼容 `取件码为`、`凭“1-3-27017”`、`货码为3-3-06006，8-5-06003` 等写法
- 设置为全屏页面，分组展示识别提示词、高级规则、桌面角标等内容，底部固定 `保存并刷新` 按钮；支持用普通提示词扩展识别范围，只有遇到特殊平台时才需要补充高级正则规则；内置 `恢复默认设置`，提示词为空或高级规则语法错误时不允许保存
- 设置页提供角标刷新频率配置和 `关于` 入口，关于弹窗会显示当前程序版本号
- 重新设计了更符合“短信取件码助手”语义的应用图标
- 全程离线运行，不申请网络权限

## 权限说明

- 应用核心读取能力以 `v1.0.12` 代码版本为准，不再要求用户将应用设置为默认短信应用
- Android 13 及以上系统需要允许通知权限后，桌面角标数字才会显示；不同桌面启动器可能会显示数字角标或通知圆点
- 部分厂商系统会将物流平台短信归类为“通知类短信”或类似受保护通道。以小米系统为例，除普通短信读取授权外，还需要在系统设置中额外开放此类通知短信访问权限，否则系统短信列表里可见的物流消息仍可能无法被应用读取
- 如果复制同一条短信内容后由本机号码重新发送，应用可以识别，而原始平台短信无法识别，通常就是厂商短信权限分流导致，不是取件码正则规则本身的问题

## 构建发布

本仓库正式交付以 GitHub Actions 为准：推送到 `main` 后会执行构建校验并上传 APK artifact；推送 `v*` 标签后会在 Releases 页面创建正式版本并附带可下载 APK。
