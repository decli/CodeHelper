# 取件码助手（CodeHelper）

一款为老人场景设计的本地短信取件码助手。

## 功能

- 首屏默认读取最近 12 小时短信，只展示未取件码
- 首页采用「待取数量大数字」英雄区（右上角内嵌时间范围胶囊）+「待取 / 全部」分段控件 + 待取列表的信息层级，首屏只保留一行控件，打开应用第一眼就能看到还有几个包裹待取、第一张取件码卡完整可见
- 全新「柿柿如意」视觉主题：柿橙表示待办、松绿表示完成，取件码以取件小票样式大字号居中展示，浅色 / 深色模式均已适配
- 取件码字号按卡片宽度自适应放大：每个取件码渲染成独立的单行文本（一码一行、永不折行），字号用 `TextMeasurer` 逐档实测，取「最长的码单行放得下」的最大值（16–72sp），同一张卡片里的多个取件码逐行展示并保持同一字号，方便老人在驿站直接出示
- 时间范围默认 `最近 12 小时`，显示在英雄卡右上角的柿橙描边胶囊上（如 `最近 12 小时 ⌄`）；点击胶囊弹出大字号、大行高的时间选择面板，可选 `最近 12 小时`、`最近 1 天` 至 `最近 14 天` 共 7 档，选择后立即重新读取短信
- 当前时间范围会扫描本机短信表中的全部短信记录，不再只依赖单一 `Inbox` 视图，减少同一发件人历史取件码漏读
- 同时兼容 `SMS + MMS` 两类本机接收消息，减少“菜鸟驿站”这类平台消息在系统短信列表可见、但应用内漏读的情况
- 仅展示本机收到的取件码，不展示本机发出的短信内容
- 待取数量统计会按未取件的实际取件码条数累加，同一短信里有 3 个取件码就计 3 个
- 桌面图标角标会显示当前时间范围内的未取件码数量，默认每 5 分钟自动刷新一次，刷新频率可在设置中调整；角标依赖一条可清除通知，手动清除通知或点击桌面图标导致角标隐藏后，会在下次刷新时重新发出通知并恢复
- 列表上方提供「待取包裹 / 全部包裹」分段控件：点 `全部包裹` 会重新加载当前时间范围内的全部取件码（含已取件），点 `待取包裹` 回到默认视图；选中态与时间筛选完全一致（柿橙实心底 + 白色对勾），全应用只有一种「选中」语言
- 未取件卡片常驻 `我已取到` 大按钮与 `查看短信` 按钮，点 `我已取到` 立即标记为已取件并从待取列表消失，同时弹出带 `撤销` 的提示条支持一步恢复；左滑展开抽屉标记、双击卡片打开短信两个手势仍然保留
- 已取件卡片支持恢复为未取件：左滑露出柿橙色 `恢复未取` 抽屉，卡片底部也常驻可见的 `恢复未取` 按钮（不依赖手势），点错「我已取到」随时可以改回来
- 已取件卡片在 `全部包裹` 标签中始终排在未取件之后；未取件按短信时间倒序排列
- 卡片底部的识别说明显示实际命中的提示词（如 `识别依据：「取件码」`），自定义正则命中时显示 `高级规则N`
- 短信时间以 `今天 14:32`、`昨天 09:15` 的口语化格式展示，更早的短信显示完整日期
- 同一条短信里的多个取件码会聚合到一张卡片里，卡片内按行展示，每个取件码一行
- 默认提取逻辑会在 `取件码`、`提货码`、`货码`、`驿站码`、`凭` 等提示词后面，自动识别一个或多个由字母、数字、连字符组成的取件码，兼容 `取件码为`、`凭“1-3-27017”`、`货码为3-3-06006，8-5-06003` 等写法
- 设置为全屏页面，分组展示识别提示词、高级规则、桌面角标等内容，底部固定 `保存并刷新` 按钮；支持用普通提示词扩展识别范围，只有遇到特殊平台时才需要补充高级正则规则；内置 `恢复默认设置`，提示词为空或高级规则语法错误时不允许保存
- 设置页提供角标刷新频率配置和 `关于` 入口，关于弹窗会显示当前程序版本号
- 重新设计了更符合“短信取件码助手”语义的应用图标
- 全程离线运行，不申请网络权限

## 权限说明

- 应用核心读取能力以 `v1.0.12` 代码版本为准，不再要求用户将应用设置为默认短信应用
- Android 13 及以上系统需要允许通知权限后，桌面角标数字才会显示；不同桌面启动器可能会显示数字角标或通知圆点
- 部分厂商系统会将物流平台短信归类为“通知类短信”或类似受保护通道。以小米系统为例，除普通短信读取授权外，还需要在系统设置中额外开放此类通知短信访问权限，否则系统短信列表里可见的物流消息仍可能无法被应用读取
- 如果复制同一条短信内容后由本机号码重新发送，应用可以识别，而原始平台短信无法识别，通常就是厂商短信权限分流导致，不是取件码正则规则本身的问题

## 构建发布

本仓库正式交付以 GitHub Actions 为准：推送到 `main` 后会执行构建校验并上传 APK artifact；推送 `v*` 标签后会在 Releases 页面创建正式版本并附带可下载 APK。

## 发布签名配置（升级安装必读）

**问题背景**：`v1.1.1` 及更早版本的 CI 在每次构建时现场生成一个新的签名密钥，导致每个版本的 APK 签名都不同。Android 要求升级包与已装应用签名一致，因此旧版本用户覆盖安装新版会报「应用未安装 / 与已安装应用签名不一致」（`INSTALL_FAILED_UPDATE_INCOMPATIBLE`），只能先卸载旧版再安装。

现在的 workflow 已改为优先使用仓库 Secrets 中的**固定签名密钥**。维护者只需一次性完成以下配置：

1. 在本地生成正式密钥库（密码请换成自己的，并妥善保管该文件——**丢失后将再次无法覆盖升级**）：

   ```bash
   keytool -genkeypair -v \
     -keystore codehelper-release.keystore \
     -alias codehelper \
     -keyalg RSA -keysize 2048 -validity 36500 \
     -storepass '你的密码' -keypass '你的密码' \
     -dname "CN=CodeHelper,O=CodeHelper,C=CN"
   ```

2. 把密钥库转成 base64 文本（macOS 用 `base64 -i codehelper-release.keystore | tr -d '\n'`）：

   ```bash
   base64 -w0 codehelper-release.keystore
   ```

3. 到 GitHub 仓库 `Settings → Secrets and variables → Actions` 添加 4 个 Repository secret：

   | Secret 名称 | 值 |
   | --- | --- |
   | `RELEASE_KEYSTORE_BASE64` | 第 2 步输出的 base64 文本 |
   | `RELEASE_STORE_PASSWORD` | 密钥库密码 |
   | `RELEASE_KEY_ALIAS` | `codehelper` |
   | `RELEASE_KEY_PASSWORD` | 密钥密码 |

4. 重新触发一次发布。**注意**：从「临时密钥版本」升到「固定密钥后的第一个版本」仍需最后卸载一次旧版；此后所有版本都能直接覆盖安装升级。

未配置 Secrets 时 workflow 仍会回退为一次性密钥并在构建日志里给出警告，便于 fork 仓库跑通构建，但产出的 APK 不具备可升级性。

另外两个覆盖安装的必要条件（workflow 已满足/需人工遵守）：每次发版 `versionCode` 必须递增；不要用低版本覆盖高版本。
