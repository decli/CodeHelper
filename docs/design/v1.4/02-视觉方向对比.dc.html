02 · 视觉方向对比 · 首页（待取列表）

三个方向 · 同一份数据、同一套语义色

共同前提（来自调研）：① 用户是老人，首屏只回答「几个包裹、码是多少」；② 柿橙=待办、松绿=完成 的语义不变；③ 「更大更少」——去掉短信正文、识别依据等次级信息，取件码成为卡片唯一主角；④ 每张卡只有一个主按钮，其余动作降级为文字按钮；⑤ 新增：点码放大出示 / 复制 / 播报，按驿站分组。
三个方向的差异在「首屏结构」与「材质感」，而不是配色。

最激进的「更大更少」：一屏只出示一个包裹，像登机牌一样左右翻。取件码可到 66–110sp，主按钮 68dp。柿霜底色让白卡片更突出。
风险：横滑手势对老人不友好（需保留左右箭头按钮替身）；多包裹时总览能力弱，依赖顶部数字。
共同的信息架构改动
  • 删：短信正文摘要、识别依据、顶栏「设置」文字（改 48dp 圆形图标按钮）
  • 并：英雄卡 → 纯排版数字，节省一张卡片高度
  • 分组：按驿站 / 发件方分节标题，同店多件一眼可见
  • 动作层级：绿色「我已取到」唯一主按钮；看短信 / 复制 / 读给我听 为文字按钮
  • 点取件码 → 全屏放大出示页（含复制、播报、亮度拉满）
推荐与理由

推荐以 1a 为基底落地，吸收 1b 的「驿站名进卡头」与 1c 的全屏出示页。理由：老人用户对熟悉度极敏感，1a 与 v1.3 保持同一心智模型且工程改动最小（无新令牌）；1b 的高对比可作为「深色模式 / 强光模式」的来源；1c 适合作为「出示模式」而非首页。03 原型据此实现。

下一步可以说

「原型改用 1b 的墨色顶带」· 「1a 卡头加驿站名」· 「1c 做成出示模式的翻页」· 「三个方向都出深色版」
