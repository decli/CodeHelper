# 适老化界面重构提案（v1.3）

> 状态：**待确认**。本文对应 2026-08 的界面评审：其中 4 项直接问题已随 `v1.2.0` 修复上线，
> 本文余下部分是首页信息架构的进一步重构提案，确认后再实现。

## 已随 v1.2.0 上线的修复

| 改动 | 说明 |
| --- | --- |
| 取件码自适应放大 | `TextAutoSize.StepBased(20sp–72sp)`，在不折行的前提下按卡片宽度尽可能大；同一张卡里多个码保持同一字号；待取数量大数字 56→72sp |
| 选中态统一 | 「待取包裹 / 全部包裹」由下划线 Tab 改为与时间筛选一致的实心分段控件（柿橙实心底 + 白色对勾），全应用一种「选中」语言 |
| 已取件可恢复 | 已取件卡片左滑露出「恢复未取」抽屉；同时卡片底部常驻可见的「恢复未取」按钮（手势必有按钮替身） |
| 升级安装报错修复 | CI 改为优先使用仓库 Secrets 中的固定签名密钥，覆盖安装不再因签名不一致失败（配置步骤见 README「发布签名配置」） |

## v1.3 提案：时间筛选并入英雄卡

### 动机

现状首屏纵向堆叠：顶栏 → 英雄卡 → 时间分段行 → 待取/全部分段行 → 列表。
两行控件挤占了约 100dp 高度，导致第一张取件码卡片贴底、第二张完全不可见。
对老人来说，首屏最该回答的问题是「有几个包裹、码是多少」。

### 方案

1. 时间范围从独立分段行收进英雄卡右上角的「最近 12 小时 ⌄」胶囊按钮（高度 ≥48dp），
   点开现有的底部时间面板换档；
2. 时间面板补充「12小时内」档位（当前面板刻意排除了默认档，因为分段行承担了它）；
3. 首屏从两行控件减为一行（只保留「待取包裹 / 全部包裹」），省出的空间还给列表：
   第一张卡完整可见（含操作按钮），第二张卡探头，暗示可下滑；
4. 业务逻辑零改动：`CodeFilterWindow`、`HomeViewModel` 均不变，纯 UI 层调整。

### 取舍（需要维护者拍板）

- 「回到 12 小时」从 1 步变 2 步（胶囊 → 面板选「12小时内」）。
  换来的是首屏一整行空间。若认为不值，保留 v1.2.0 的双排分段布局即可，
  选中语言已统一，不影响其余修复。

### 设计原则（参考对象）

| 原则 | 参考 |
| --- | --- |
| 一屏只答一个问题，关键数字宽度自适应、永不折行 | 支付宝长辈模式 |
| 全应用一种选中语言：柿橙实心底 + 对勾 | 微信关怀模式 |
| 手势必有按钮替身，可见按钮 ≥48dp | WCAG 2.5 |
| 取件小票比喻：撕票线 + 居中大码 | 菜鸟驿站取件凭证 |
